# ADR-020 – CareFlow Development Framework

## Status

Accepted

## Hinweis

Diese ADR rekonstruiert eine bereits fachlich getroffene Entscheidung, die im ADR-Verzeichnis noch nicht dokumentiert war.

## Kontext

CareFlow entwickelt sich von einem MVP zu einem fachlich anspruchsvollen Führungs- und Validierungssystem für Pflegeeinsatzplanung.

Dafür braucht das Projekt nicht nur Code, sondern ein konsistentes Entwicklungsframework, das Fachlogik, Architektur, Tests, Dokumentation, KI-Nutzung und Produktpositionierung verbindet.

## Entscheidung

CareFlow verwendet ein eigenes Development Framework.

Dieses Framework beschreibt, wie CareFlow fachlich und technisch weiterentwickelt wird.

Es umfasst insbesondere:

- Produktpositionierung
- Architekturentscheidungen
- ADRs
- Entwicklungszyklus
- KI-Einsatzmatrix
- Testing
- Dokumentation
- Governance
- README
- AGENTS-Anweisungen
- fachliche Roadmap

## Begründung

CareFlow ist kein rein technisches Experiment. Es verbindet Pflegeführung, Planung, Validierung, Organisationsentwicklung, Controlling und spätere Lernlogik.

Damit diese Komplexität kontrolliert wachsen kann, braucht das Projekt ein gemeinsames Entwicklungsverständnis.

Das Development Framework hilft, neue Funktionen nicht isoliert, sondern im Zusammenhang mit der Gesamtlogik von CareFlow zu entwickeln.

## Bestandteile

Das CareFlow Development Framework umfasst:

- README als Projektüberblick
- AGENTS.md als Arbeitsanweisung für KI-gestützte Entwicklung
- ADRs als Architekturentscheidungen
- standardisierten Entwicklungszyklus
- KI-Einsatzmatrix
- Tests und Reviewlogik
- Dokumentationsstandard
- fachliche Roadmap
- Produktprinzipien

## Leitprinzipien

CareFlow soll:

- klein und kontrolliert wachsen
- fachlich erklärbar bleiben
- Human-in-the-Loop respektieren
- bestehende Planungssysteme ergänzen
- Validierungen nachvollziehbar machen
- Führung unterstützen statt ersetzen
- langfristig organisationales Lernen ermöglichen

## Konsequenzen

Grössere Änderungen sollen mit dem Development Framework abgeglichen werden.

Neue Module sollen nicht nur technisch funktionieren, sondern zur CareFlow-Produktlogik passen.

README, AGENTS.md und ADRs sollen bei relevanten Änderungen gepflegt werden.

## Nicht-Ziele

Diese ADR führt nicht ein:

- starres Prozesshandbuch
- vollständige Enterprise-Architektur
- schwergewichtige Projektbürokratie
- formales Qualitätsmanagementsystem

## Zusammenfassung

Das CareFlow Development Framework bündelt die fachlichen, technischen und methodischen Grundlagen der Weiterentwicklung. Es sorgt dafür, dass CareFlow kontrolliert, nachvollziehbar und kohärent wächst.
